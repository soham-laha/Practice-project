## Screenshot investigation: what is and is not established

- **Lite's rejection means no item passed the complete guardrail.** It does not identify which certificate failed, prove poor image quality, or show that the input exceeded its ~0.37 MB size. The old catch discarded that distinction. Tests now deliberately generate duplicate options, bad derivations/units/recoveries and undeclared symbols and verify safe, specific rejection without releasing an item.
- **Flash's “unreachable” could have represented either a request/network exception or the old shared 75-second timeout path.** The screenshot alone cannot distinguish those or establish a bad key/model. These paths are now separated and tested with cancelled/failed mocked transports.
- The implementation previously described the full schema only in the system prompt. Adding provider-constrained JSON and more faithful grammar guidance addresses a real contract gap, **not a demonstrated root-cause fix for this particular source**.
- Every click still makes **at most one provider call**. There is no hidden paid retry/repair loop, model switch, weakened symbolic test, fabricated fallback drill or key persistence on the server. The user can deliberately retry or use the free reference flow.
