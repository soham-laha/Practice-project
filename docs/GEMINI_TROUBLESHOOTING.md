# Gemini generation contract repair and diagnostics

## What the screenshots establish

The supplied Flash Lite message says the returned content failed the strict item contract. That is a **format rejection**, not evidence of exhausted quota or necessarily a SymPy rejection. The Flash “unreachable” message is ambiguous: it does not distinguish frontend/backend deployment, transport failure or a deadline. The below-limit AI Studio charts do not explain either failure, but are good reason not to blame everything on quota. They also do not prove that a particular request/model alias/settings combination succeeded.

The original problem, raw provider result and corresponding exception are not available. No exact root cause or successful live-generation fix is claimed from those screenshots. Never share an API key or private source in an issue/chat to investigate them.

## Generation-path repairs in this branch

These are application fixes, separate from the earlier error-message/receipt work:

1. **Use an actual Gemini decoding contract, not raw Pydantic schema.** The previous payload included `const`, `pattern`, `default`, string-length and exclusive-bound keywords outside the provider's documented subset. In particular, `schema_version`, fixed marks and A–D IDs depended on `const`/`pattern`, while the selected exam, pacing and negative marks were not specialized. `backend/app/generation_schema.py` now projects the public contract onto supported keywords, translates literals and A–D IDs to supported string/numeric **enums**, fixes the conservative uncalibrated parameter values already required by the prompt, and constrains the selected mode's timing/marks. The prompt requested **one** problem but the old decoding schema allowed five; the request now sets `minItems=maxItems=1`. Each call builds an independent schema, so Main/Advanced constraints cannot leak between concurrent requests.
2. **Keep unsupported constraints as instructions and enforce them downstream.** String lengths/patterns and the eight-symbol bound remain in field descriptions/system instructions, with full final Pydantic enforcement. The public 1–5-item parser remains compatible; requests ask for exactly one. Only documented supported keywords are sent, all local `$ref`s resolve at the root with no forbidden non-`$` siblings, and no literal/default/marking constraint is silently treated as provider-enforced when it is not. The keyword reference is the [pinned Google API declaration](https://github.com/googleapis/googleapis/blob/bc7e3baa28fbb223fa93782e130260fab8205bfc/google/ai/generativelanguage/v1beta/generative_service.proto#L427-L472). Unsupported keywords in the former payload are a concrete compatibility/constraint gap, **not proof of the original screenshot's exact cause or a guaranteed provider HTTP 400**.
3. **Close a server/browser contract mismatch.** The API previously accepted empty diagram `label`/`description` values, then the browser rejected that otherwise successful response. Both now require at least one character; the generator is explicitly told to use readable metadata or `diagram_anchors: []`, not empty placeholders. Invalid metadata fails before an HTTP-success drill is issued. No source text or diagram description is fabricated to make it pass.
4. **Exercise the successful handoff, not only rejection screens.** Four browser regressions cover Main/Advanced × Flash/Lite with author-owned, non-reference lift/spring fixtures. Each response is first produced by the real FastAPI → Pydantic → isolated SymPy pipeline with **only Google's transport mocked**, then consumed by the real browser parser, review screen and forged-session handoff. Tests assert one request, selected model/exam/marks, canonical checked math, no early session, no key in session storage and no reference-drill substitution. These are controlled successful integration fixtures, **not live Gemini output**. The hosted workflow now installs the local Python fixture dependencies; the fixtures never call the public API to generate content.

Regressions also confirm final rejection of invalid IDs/version, wrong Main marks/pacing, out-of-range parameters, oversized recovery expressions, too many domain entries and incomplete diagram metadata, without reaching the algebra worker or starting a paid repair. The existing real-algebra rejection tests remain in place. The coach keeps its existing unstructured 1,800-token budget and single-call behavior.

**Verification (local):** 137 backend tests with warnings as errors; 103 frontend unit tests; 27 browser passes with three public-only skips (30 cases). Lint, types, formatting, build and local smoke are recorded in the current review. There is still no original failing provider result or authorized live request: the changes fix the demonstrated contract gaps, but the persistent **public** failure is not declared resolved until updated services and a real browser request pass.

## Safe failure contract

Strict schema-constrained generation and independent fail-closed Pydantic/SymPy verification remain in place. No guardrail was relaxed and no hidden paid repair/retry loop was added. Error responses now include only static `detail` text and four allowlisted diagnostic fields:

```json
{
  "detail": "A fixed, actionable explanation; never the raw provider response.",
  "diagnostic": {
    "code": "item_contract",
    "stage": "format",
    "request_id": "123456abcdef",
    "revision": "1234abcd"
  }
}
```

The values above are illustrative fixtures, not a real failure receipt. A request ID is 12 hex characters; an API revision is eight hex characters or `workspace`. No key, filename, input, provider body, Pydantic input/context, native exception/cause or learner history is retained in the diagnostic receipt. Unknown response fields are discarded by the browser's diagnostic parser. Request IDs do not imply a stored server-side learner/request log.

| Stage / code                                                                      | Meaning / next action                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `provider_access`                                                                 | Google denied the key/model access. Known Google **400 `API_KEY_INVALID`** is classified here as well as 401/403. Check the key's project, access and restrictions in AI Studio; Save itself is format-only.                                             |
| `provider_quota`                                                                  | Google actually returned **429** for this request/key/model. This is the quota-specific category. A full API worker queue can also return HTTP 429 but is **not** labelled as confirmed Gemini quota exhaustion.                                         |
| `provider_model`, `provider_request`                                              | Alias unavailable, or source/generation settings rejected. A Google 400 is not automatically a quota or key verdict. Check deployed revisions and model access/settings.                                                                                 |
| `provider_timeout`, `provider_network`, `provider_unavailable`                    | Separate whole-call deadline, network failure and non-success provider response. The frontend/backend may also be unavailable or warming up; the old “unreachable” text alone cannot identify which.                                                     |
| `provider_blocked`, `provider_stopped`, `provider_output_limit`, `provider_empty` | Blocked/incomplete/truncated/empty output is not released as a question. Thought-only text is not treated as final JSON.                                                                                                                                 |
| `format` / `item_contract`                                                        | Gemini answered but failed the item format, required recovery fields, exam/pacing/marking rules, types/lengths or unique IDs. A bounded fixed category is shown, never an unknown field path or raw generated answer. Spare quota does not prevent this. |
| `verification` / `verification_rejected`, `verification_timeout`                  | The independently bounded algebra check rejected the supplied certificate or reached its deadline. This can be a generated-expression/units/option/recovery problem; it is not proof that the image is unreadable.                                       |

The forge keeps the source and saved key after failure, does not create a forged-session handoff, and offers a free reference drill. **Technical details → Copy safe diagnostics** gives the model actually used, interface/API revisions, HTTP status, stage, code and request ID. It intentionally omits even the error message and source filename. Transport failures/older builds may have no diagnostic metadata; the receipt explicitly says so.

5. Only when the owner chooses to incur provider usage: save a key **in the browser, not chat or hosting environment**, submit one small complete text problem once, and inspect the new stage/code if it fails.
